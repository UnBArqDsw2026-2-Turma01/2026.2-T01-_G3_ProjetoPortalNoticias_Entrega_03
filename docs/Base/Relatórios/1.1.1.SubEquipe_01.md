## Contexto (Problema)
### 1. Builder de notícias - João Pedro Lopes da Cruz

Pensando na funcionalidade de criar uma notícia pensei que poderia haver templatezinho de estrutura de como ficaria a página da notícia, alguns com a imagem em destaque grande, outro com apenas uma imagem pequena ao lado do texto e uma notícia que comporte um carrossel de imagens. Pensando nessas estruturas pré definidas optei por implementar a geração da página usando um builder, pois todas as notícias seguirão a mesma estrutura base de informações (mídias, texto, título, categoria, autor, etc).



### 2. Singleton do Repositório de Notícias - Giovanna Felipe Guimaraes

No portal, várias telas dependem das mesmas notícias publicadas: a página inicial mostra as mais recentes, a página de categoria filtra por assunto e a área de destaques puxa as principais. Se cada uma dessas telas criasse o seu próprio repositório de notícias, cada uma teria a sua própria cópia dos dados. Assim, uma notícia publicada poderia aparecer na home e não aparecer na categoria, ou aparecer duplicada, além de abrir várias "conexões" para buscar a mesma informação sem necessidade. Por isso escolhi o Singleton para o repositório de notícias: ele garante que exista uma única instância guardando as notícias publicadas e oferece um ponto de acesso global a ela. Com isso, toda tela que chama o repositório recebe o mesmo objeto, e o que é publicado num lugar aparece igual em todos os outros. Ele também se conecta ao Builder do João, porque a notícia que o Builder monta é publicada nesse repositório único.

**1. A interface do Builder** (`js/builders.js`)

O JavaScript não tem `interface` como o Java, então criei a `NoticiaBuilder` como uma classe que não pode ser instanciada diretamente (o construtor verifica `new.target`) e cujos métodos lançam erro se não forem sobrescritos. Assim, ela funciona como um contrato: todo builder concreto precisa saber executar os mesmos passos de montagem da notícia.

```js
class NoticiaBuilder {
  constructor() {
    if (new.target === NoticiaBuilder) {
      throw new Error("NoticiaBuilder é uma interface: use NoticiaDestaqueBuilder, NoticiaCompactaBuilder ou NoticiaMistaBuilder.");
    }
  }

  reset() { throw new Error("reset() não implementado"); }
  definirCabecalho(titulo, categoria, capa) { throw new Error("definirCabecalho() não implementado"); }
  definirSubtitulo(subtitulo) { throw new Error("definirSubtitulo() não implementado"); }
  definirAutor(autor) { throw new Error("definirAutor() não implementado"); }
  adicionarTexto(texto) { throw new Error("adicionarTexto() não implementado"); }
  adicionarImagem(img) { throw new Error("adicionarImagem() não implementado"); }
  adicionarCarrossel(imgs) { throw new Error("adicionarCarrossel() não implementado"); }
  adicionarTopicos(itens) { throw new Error("adicionarTopicos() não implementado"); }
  definirRodape(fonte) { throw new Error("definirRodape() não implementado"); }
  getResultado() { throw new Error("getResultado() não implementado"); }
}
```

**2. Os builders concretos: mesmos passos, visuais diferentes**

Os três builders recebem exatamente as mesmas chamadas, mas cada um decide como configurar cada parte da notícia. O `NoticiaDestaqueBuilder` coloca a capa grande ocupando toda a largura, aplica a letra capitular no primeiro parágrafo e mostra as imagens em largura total. O `NoticiaCompactaBuilder` usa uma capa em miniatura e coloca as imagens menores ao lado do texto. Comparando o mesmo método nos dois, dá para ver a diferença:

```js
// NoticiaDestaqueBuilder
adicionarTexto(texto) {
  this.noticia.adicionar(new TextoBloco(texto, { capitular: this.primeiroTexto }));
  this.primeiroTexto = false;
}

adicionarImagem(img) {
  this.noticia.adicionar(new ImagemBloco(img.url, { legenda: img.legenda, largura: 100 }));
}

// NoticiaCompactaBuilder
adicionarTexto(texto) {
  this.noticia.adicionar(new TextoBloco(texto));
}

adicionarImagem(img) {
  this.noticia.adicionar(new ImagemBloco(img.url, { legenda: img.legenda, largura: 40, alinhamento: "direita" }));
}
```

O `NoticiaMistaBuilder` mistura os dois: a capa fica em destaque com o título e o subtítulo escritos sobre a imagem, o primeiro parágrafo tem capitular e as imagens do corpo ficam ao lado do texto. A posição do título sobre a capa é uma decisão de apresentação, e não de conteúdo, por isso ela é passada no construtor do builder e não passa pelo Director. O construtor também recusa posições inválidas.

```js
const PosicaoTitulo = Object.freeze({
  SUPERIOR_ESQUERDA: "superior-esquerda",
  SUPERIOR_DIREITA: "superior-direita",
  INFERIOR_ESQUERDA: "inferior-esquerda",
  INFERIOR_DIREITA: "inferior-direita",
  CENTRO: "centro",
});

class NoticiaMistaBuilder extends NoticiaBuilder {
  constructor(posicaoTitulo = PosicaoTitulo.INFERIOR_ESQUERDA) {
    super();
    if (!Object.values(PosicaoTitulo).includes(posicaoTitulo)) {
      throw new Error(`Posição do título inválida: ${posicaoTitulo}`);
    }
    this.posicaoTitulo = posicaoTitulo;
    this.reset();
  }
  ...
}
```

Em todos os builders, o `getResultado()` entrega a notícia pronta e já chama o `reset()`, deixando o builder limpo para montar a próxima notícia sem herdar blocos da anterior.

```js
getResultado() {
  const resultado = this.noticia;
  this.reset();
  return resultado;
}
```

**3. O Director e o roteiro do redator** (`js/director.js`)

Essa é a parte central do por quê o builder foi usado, os blocos de uma notícia aparecem na ordem que o redator escolheu, então o Director recebe essa ordem como um roteiro, uma lista de itens, em que cada item tem um tipo (`TEXTO`, `IMAGEM`, `CARROSSEL` ou `TOPICOS`) e o seu conteúdo. O `construirPersonalizada()` monta primeiro o cabeçalho e depois percorre o roteiro chamando o passo correspondente do builder. O Director só conhece a interface `NoticiaBuilder`, então ele não sabe (e não precisa saber) qual builder concreto está usando.

```js
construirPersonalizada(titulo, subtitulo, categoria, capa, autor, roteiro, fonte) {
  this.validar(roteiro);

  this.builder.reset();
  this.builder.definirCabecalho(titulo, categoria, capa);
  if (subtitulo) {
    this.builder.definirSubtitulo(subtitulo);
  }
  this.builder.definirAutor(autor);

  for (const item of roteiro) {
    switch (item.tipo) {
      case TipoBloco.TEXTO:
        this.builder.adicionarTexto(item.conteudo);
        break;
      case TipoBloco.IMAGEM:
        this.builder.adicionarImagem(item.conteudo);
        break;
      case TipoBloco.CARROSSEL:
        this.builder.adicionarCarrossel(item.conteudo);
        break;
      case TipoBloco.TOPICOS:
        this.builder.adicionarTopicos(item.conteudo);
        break;
    }
  }

  if (fonte) {
    this.builder.definirRodape(fonte);
  }
}
```

Antes de chamar qualquer passo, o método privado `validar()` confere o roteiro: ele não pode estar vazio, um texto não pode estar em branco, uma imagem precisa de URL, o carrossel precisa de pelo menos 2 imagens e a lista de tópicos não pode estar vazia. Se algo estiver errado, o Director recusa o roteiro e informa qual bloco tem problema. Na página "Montar notícia", essa mensagem aparece para o redator na etapa de revisão. O Director também oferece o `construirNoticiaPadrao()`, uma receita fixa para notícias simples (cabeçalho, autor e um único texto).

**4. O produto: a Notícia** (`js/noticia.js`)

O objeto `Notícia` guarda as informações gerais (título, subtítulo, categoria, capa, autor, rodapé) e a lista de blocos do corpo. A `variante` é definida pelo builder concreto que a criou e é ela que aplica o CSS de cada versão. A data de criação é gerada automaticamente no construtor, então nem o Cliente nem o Builder informam a data, como está na nota do diagrama.

```js
class Noticia {
  constructor(variante) {
    this.variante = variante; // "destaque" | "compacta" | "mista", definida pelo builder concreto
    this.posicaoTitulo = null; // só a versão mista usa: onde o título fica sobre a capa
    this.titulo = "";
    this.subtitulo = "";
    this.categoria = "";
    this.capa = null; // ImagemBloco
    this.autor = null; // Autor
    this.dataCriacao = new Date(); // gerada automaticamente: ninguém de fora define a data
    this.blocos = [];
    this.rodape = "";
  }

  adicionar(bloco) {
    this.blocos.push(bloco);
  }
  ...
}
```

O método `renderizar()` monta o HTML da página inteira (cabeçalho, autor, ações de compartilhar e salvar, capa, corpo e rodapé) e, para o corpo, apenas pede a cada bloco que se renderize.

**5. As partes do produto: os blocos** (`js/blocos.js`)

Essa é a composição entre `Noticia` e `Bloco` que a IA sugeriu na revisão do diagrama. `Bloco` é uma classe abstrata (também protegida com `new.target`), e cada tipo de bloco sabe gerar o seu próprio HTML. Os blocos recebem opções de configuração (capitular, largura, alinhamento, modo do carrossel), e são os builders concretos que escolhem essas opções. É por isso que o mesmo roteiro gera páginas diferentes.

```js
class Bloco {
  constructor() {
    if (new.target === Bloco) {
      throw new Error("Bloco é abstrato: use TextoBloco, ImagemBloco, CarrosselBloco ou TopicosBloco.");
    }
  }

  renderizar() {
    throw new Error("renderizar() deve ser implementado pela subclasse.");
  }
}

class CarrosselBloco extends Bloco {
  constructor(imagens, { modo = "slides" } = {}) {
    super();
    this.imagens = imagens; // [{ url, legenda }]
    this.modo = modo; // "slides" (um por vez, com setas) | "miniaturas" (faixa rolável)
  }
  ...
}
```

Todo texto informado pelo usuário passa pela função `escaparHtml()` antes de entrar no HTML, para evitar que um título ou legenda injete código na página.

**6. O Cliente** (`js/cliente.js` e `js/montar-noticia.js`)

O Cliente escolhe qual builder concreto vai ser usado, transforma os dados da notícia no roteiro, entrega tudo ao Director e, no final, pede o resultado ao builder. Trocar o visual da notícia é só trocar o builder passado ao Director, sem mexer em nenhuma outra linha.

```js
const builders = {
  destaque: () => new NoticiaDestaqueBuilder(),
  compacta: () => new NoticiaCompactaBuilder(),
  mista: () => new NoticiaMistaBuilder(seletorPosicao.value),
};

const builder = builders[versao]();
const director = new NoticiaDirector(builder);

director.construirPersonalizada(
  exemplo.titulo,
  exemplo.subtitulo,
  exemplo.categoria,
  exemplo.capa,
  new Autor(exemplo.autor.nome, exemplo.autor.foto),
  roteiroDoExemplo(exemplo),
  exemplo.fonte
);
const noticia = builder.getResultado();
conteudo.innerHTML = noticia.renderizar();
```

Na página "Montar notícia", o formulário preenchido pelo redator é convertido no mesmo tipo de roteiro (`List<ItemRoteiro>`), respeitando a ordem em que os blocos foram adicionados, e segue exatamente o mesmo caminho até o Director.

### 2. Singleton do Repositório de Notícias

O código está em [demonstracao_codigos/SubGrupo1/singleton](https://github.com/UnBArqDsw2026-2-Turma01/2026.2-T01-_G3_ProjetoPortalNoticias_Entrega_03/tree/subgrupo-1/demonstracao_codigos/SubGrupo1/singleton). A implementação foi feita em JavaScript puro e pode ser executada de duas formas:

- **Terminal:** na pasta do padrão, executar `node demo.js` (ou `node demo.js --pausar`, que avança uma etapa por vez ao pressionar ENTER).
- **Navegador:** abrir o arquivo `index.html`, que reproduz a Página inicial e as páginas de categoria do protótipo no Figma. No painel do Singleton (canto inferior direito), selecionar uma notícia e um builder e clicar em "Publicar no repositório"; a notícia passa a aparecer no Destaque, nas Últimas notícias e na página da categoria correspondente.

As duas versões compartilham os mesmos arquivos e reutilizam diretamente o código do Builder (pasta `../builder`), sem duplicá-lo.

**1. A instância única e o construtor bloqueado** (`js/repositorioNoticias.js`)

Como o JavaScript não oferece construtores privados, como ocorre em Java, utilizei um atributo estático privado (`#liberado`) como mecanismo de controle: o construtor só pode ser executado quando a chamada parte do próprio `getInstancia()`. Qualquer tentativa externa de instanciar a classe com `new RepositorioNoticias()` lança uma exceção.

```js
class RepositorioNoticias {
  static #instancia = null;
  static #liberado = false; // só o getInstancia() pode chamar o construtor

  #noticias = [];

  constructor() {
    if (!RepositorioNoticias.#liberado) {
      throw new Error("RepositorioNoticias é um Singleton: use RepositorioNoticias.getInstancia() em vez de new.");
    }
    ...
  }
```

**2. O ponto global de acesso**

O método estático `getInstancia()` cria o repositório apenas no momento da primeira solicitação (*lazy initialization*) e, nas chamadas seguintes, retorna sempre a mesma instância. O bloco `try/finally` assegura que o mecanismo de controle seja restaurado mesmo que ocorra alguma falha durante a criação do objeto.

```js
  static getInstancia() {
    if (RepositorioNoticias.#instancia === null) {
      RepositorioNoticias.#liberado = true;
      try {
        RepositorioNoticias.#instancia = new RepositorioNoticias();
      } finally {
        RepositorioNoticias.#liberado = false;
      }
    }
    return RepositorioNoticias.#instancia;
  }
```

**3. Os dados que o Singleton protege**

A lista de notícias é encapsulada em um atributo privado (`#noticias`). O método `publicar()` impede o cadastro de notícias duplicadas, e os métodos de consulta retornam novas listas, de modo que nenhuma tela consegue alterar o estado interno do repositório. Os destaques correspondem às notícias construídas pelo `NoticiaDestaqueBuilder`.

```js
  publicar(noticia) {
    if (this.#noticias.some((n) => n.titulo === noticia.titulo)) {
      return false;
    }
    this.#noticias.push(noticia);
    return true;
  }

  listarPorCategoria(categoria) {
    return this.#noticias.filter((n) => n.categoria === categoria).reverse();
  }

  listarDestaques() {
    return this.#noticias.filter((n) => n.variante === "destaque").reverse();
  }
```

**4. Os clientes: as telas do portal** (`js/telas.js`)

As telas não armazenam cópias das notícias nem instanciam o repositório. Todas herdam da classe abstrata `Tela`, que obtém o repositório por meio de `getInstancia()` sempre que necessário.

```js
class Tela {
  get repositorio() {
    return RepositorioNoticias.getInstancia();
  }
}

class PaginaCategoria extends Tela {
  noticias() {
    return this.repositorio.listarPorCategoria(this.categoria);
  }
}
```

**5. A ligação com o Builder** (`js/redacao.js`)

A classe `Redacao` seleciona o builder concreto, delega ao `NoticiaDirector` a construção da notícia e publica o resultado no repositório único. Dessa forma, o Builder é responsável por *como* a notícia é construída, enquanto o Singleton é responsável por *onde* ela é armazenada.

```js
const builder = criarBuilder();
const director = new NoticiaDirector(builder);
director.construirPersonalizada(/* título, categoria, capa, autor, roteiro... */);
const noticia = builder.getResultado();

const publicada = RepositorioNoticias.getInstancia().publicar(noticia);
```

**Execução no terminal**

A demonstração apresenta as seguintes etapas:

1. As três telas solicitam o repositório: apenas a primeira chamada cria a instância, e as demais recebem a mesma referência (a comparação `===` resulta em `true`).
2. Uma tentativa de instanciação direta com `new RepositorioNoticias()` é bloqueada.
3. A redação publica quatro notícias construídas com os diferentes builders.
4. Cada tela consulta o mesmo repositório.
5. Uma nova notícia publicada passa a aparecer em todas as telas, sem necessidade de recriá-las.
6. A tentativa de publicar uma notícia duplicada é recusada.

