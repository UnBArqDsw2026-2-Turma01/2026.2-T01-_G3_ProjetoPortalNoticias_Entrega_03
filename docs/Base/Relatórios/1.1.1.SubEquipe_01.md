#### Contexto (Problema)
##### 1. Builder de notícias - João Pedro Lopes da Cruz

Pensando na funcionalidade de criar uma notícia pensei que poderia haver templatezinho de estrutura de como ficaria a página da notícia, alguns com a imagem em destaque grande, outro com apenas uma imagem pequena ao lado do texto e uma notícia que comporte um carrossel de imagens. Pensando nessas estruturas pré definidas optei por implementar a geração da página usando um builder, pois todas as notícias seguirão a mesma estrutura base de informações (mídias, texto, título, categoria, autor, etc).



##### 2. Singleton do Repositório de Notícias - Giovanna Felipe Guimaraes

No portal, várias telas dependem das mesmas notícias publicadas: a página inicial mostra as mais recentes, a página de categoria filtra por assunto e a área de destaques puxa as principais. Se cada uma dessas telas criasse o seu próprio repositório de notícias, cada uma teria a sua própria cópia dos dados. Assim, uma notícia publicada poderia aparecer na home e não aparecer na categoria, ou aparecer duplicada, além de abrir várias "conexões" para buscar a mesma informação sem necessidade. Por isso escolhi o Singleton para o repositório de notícias: ele garante que exista uma única instância guardando as notícias publicadas e oferece um ponto de acesso global a ela. Com isso, toda tela que chama o repositório recebe o mesmo objeto, e o que é publicado num lugar aparece igual em todos os outros. Ele também se conecta ao Builder do João, porque a notícia que o Builder monta é publicada nesse repositório único.

    A IA acertou o básico do Singleton (construtor privado, atributo estático com a instância única e um método de acesso global), mas encontrei alguns problemas. **1. A instância única e o construtor bloqueado** (`js/repositorioNoticias.js`)

Como o JavaScript não oferece construtores privados, como ocorre em Java, utilizei um atributo estático privado (`#liberado`) como mecanismo de controle: o construtor só pode ser executado quando a chamada parte do próprio `getInstancia()`. Qualquer tentativa externa de instanciar a classe com `new RepositorioNoticias()` lança uma exceção.

```js
class RepositorioNoticias {
  static #instancia = null;
  static #liberado = false; // só o getInstancia() pode chamar o construtor

  #noticias = [];

  constructor() {
    if (!RepositorioNoticias.#liberado) {
      throw new Error("RepositorioNoticias é um Singleton: use RepositorioNoticias.getInstancia() em vez de new.");
    }
    ...
  }
```

**2. O ponto global de acesso**

O método estático `getInstancia()` cria o repositório apenas no momento da primeira solicitação (*lazy initialization*) e, nas chamadas seguintes, retorna sempre a mesma instância. O bloco `try/finally` assegura que o mecanismo de controle seja restaurado mesmo que ocorra alguma falha durante a criação do objeto.

```js
  static getInstancia() {
    if (RepositorioNoticias.#instancia === null) {
      RepositorioNoticias.#liberado = true;
      try {
        RepositorioNoticias.#instancia = new RepositorioNoticias();
      } finally {
        RepositorioNoticias.#liberado = false;
      }
    }
    return RepositorioNoticias.#instancia;
  }
```

**3. Os dados que o Singleton protege**

A lista de notícias é encapsulada em um atributo privado (`#noticias`). O método `publicar()` impede o cadastro de notícias duplicadas, e os métodos de consulta retornam novas listas, de modo que nenhuma tela consegue alterar o estado interno do repositório. Os destaques correspondem às notícias construídas pelo `NoticiaDestaqueBuilder`.

```js
  publicar(noticia) {
    if (this.#noticias.some((n) => n.titulo === noticia.titulo)) {
      return false;
    }
    this.#noticias.push(noticia);
    return true;
  }

  listarPorCategoria(categoria) {
    return this.#noticias.filter((n) => n.categoria === categoria).reverse();
  }

  listarDestaques() {
    return this.#noticias.filter((n) => n.variante === "destaque").reverse();
  }
```

**4. Os clientes: as telas do portal** (`js/telas.js`)

As telas não armazenam cópias das notícias nem instanciam o repositório. Todas herdam da classe abstrata `Tela`, que obtém o repositório por meio de `getInstancia()` sempre que necessário.

```js
class Tela {
  get repositorio() {
    return RepositorioNoticias.getInstancia();
  }
}

class PaginaCategoria extends Tela {
  noticias() {
    return this.repositorio.listarPorCategoria(this.categoria);
  }
}
```

**5. A ligação com o Builder** (`js/redacao.js`)

A classe `Redacao` seleciona o builder concreto, delega ao `NoticiaDirector` a construção da notícia e publica o resultado no repositório único. Dessa forma, o Builder é responsável por *como* a notícia é construída, enquanto o Singleton é responsável por *onde* ela é armazenada.

```js
const builder = criarBuilder();
const director = new NoticiaDirector(builder);
director.construirPersonalizada(/* título, categoria, capa, autor, roteiro... */);
const noticia = builder.getResultado();

const publicada = RepositorioNoticias.getInstancia().publicar(noticia);
```

**Execução no terminal**

A demonstração apresenta as seguintes etapas:

1. As três telas solicitam o repositório: apenas a primeira chamada cria a instância, e as demais recebem a mesma referência (a comparação `===` resulta em `true`).
2. Uma tentativa de instanciação direta com `new RepositorioNoticias()` é bloqueada.
3. A redação publica quatro notícias construídas com os diferentes builders.
4. Cada tela consulta o mesmo repositório.
5. Uma nova notícia publicada passa a aparecer em todas as telas, sem necessidade de recriá-las.
6. A tentativa de publicar uma notícia duplicada é recusada.
